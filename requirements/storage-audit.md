# Browser-side storage audit

Scope: `agent-board` (core fork) `main` and `origin/local-server-v2`, `agent-board-client` `main`, `agent-board-local-server` `main`.
Method: `git grep` for `localStorage|sessionStorage|indexedDB|document.cookie|useLocalStorage|useSessionStorage|readLocalStorageValue|ColorSchemeManager|serviceWorker|caches.|Persister|keyring|app_*_dir|fs::write`, then each hit read. Test files excluded from the rows (they only exercise the keys below).

Rule under audit: localStorage/sessionStorage hold volatile state only; titles, icons, labels and anything the user would miss on another device live in the database.

Branch note: every web-storage row in `core` is identical on `origin/local-server-v2` (same files, same keys, same line numbers) except `apps/frontend/src/App.tsx`, where `removeDrafts()` sits at line 44 instead of 47. `origin/local-server-v2` adds no storage the `main` branch lacks and removes none.

Classes: `volatile` = fine to lose, per device. `content` = user would miss it on another device. `secret` = key material or token; neither volatile nor content.

## Findings

### Content currently in web storage that must move (3)

1. ST-11 `agent-board.desktopNotifications`: per-user setting `notifications.desktop` on the server. Browser permission remains per device.
2. ST-12 `agent-board.recentEmojis`: per-user setting for recent icons (cap 24). Already treated as a portable preference by the board export/import.
3. ST-13 `agent-board.lastDirectory`: classed volatile, but it is the borderline one. Either keep volatile and fix the leak below, or make it a per-user server setting `newTask.lastPlace` (machine id plus directory id, no raw path).

Borderline, left as volatile: ST-14 colour scheme (per-device, defaults to OS).

On disk (client, not web storage): ST-18 `servers.json` is the user's list of boards; it cannot live in a board database and stays a local file. ST-19 `tabs/<server>.json` holds `selected` and `path` (volatile, stays) plus `label` (see leaks).

### Plaintext of sealed content written to storage

- ST-02, ST-03, ST-05, ST-06 (sessionStorage): `DraftStore.write` stores `base` as the plain current title or prompt (`lib/drafts.ts:83-84,143,149,155,160`). Drafts also store everything the user typed. Cleared at lock and sign-out, and sessionStorage dies with the tab, but it is readable by any script on the origin while unlocked.
- ST-13 (localStorage): decrypted machine directory path, written without the key bound, persists across lock, sign-out and tab close, and is outside `BOARD_PREF_KEYS` so `clearBoardPrefs` (account deletion) skips it.
- ST-19 (client file): latent. `label` copies `document.title`; safe today only because the core frontend title is static. Any change that titles task pages with the task title will write decrypted titles to `tabs/<server>.json` in plaintext. The Rust tests already assert labels like "Fix login" (`tabs.rs:1071-1108`).
- ST-21 (client webview store): inherits all of the above and survives native sign-out.

### Keys missing from the clear-on-lock / sign-out path

- ST-13 `agent-board.lastDirectory`: not cleared by `lock()`, sign-out, or `clearBoardPrefs()`.
- ST-11, ST-12: not cleared on lock or sign-out (cleared only on account deletion via `clearBoardPrefs`). Fine if they move to the server; until then they survive sign-out on a shared browser.
- ST-14 `mantine-color-scheme-value`, ST-10 `agent-board.session-changed`: never cleared; harmless (no content, no secret).
- ST-09 verifier: not cleared on lock, but only exists between login start and return; dies with the tab.
- ST-21: client-level `sign_out` (`src-tauri/src/sign_in.rs:345`) deletes only the keychain session. The embedded profile keeps the IndexedDB keys (ST-15) and any drafts until the board's own Lock or the server is removed. [inferred from the code paths read; not run.]
- ST-15 is not cleared when the session expires (401): `App.tsx:45-48` drops drafts and modals only. Intended per the key store comments, but worth stating in the rule.
