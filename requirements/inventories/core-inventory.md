# Core inventory: the `agent-board` fork (of codeplant-de/agent-board)

Read-only inventory for the `agent-board-standalone` plan. Written 2026-11-24.

## Sources and branches read

- **`main`** at `011f7be` (fork PR #52). This is the checked-out branch; every requirement below is read from it unless it says `local-server-v2`.
- **`upstream/main`** at `ab3dce8` (upstream #169, 2026-11-19), after `git fetch upstream`. The fork's `main` is **40 commits ahead and 0 behind**: it no longer mirrors upstream. Fork PRs #8–#52 are all fork-only.
- **`origin/local-server-v2`** at `e1f0dcd`. It is 36 commits ahead of `main` and 18 behind (it does not have `main`'s last 18 commits, e.g. #47–#52 migration engine, self-update `--rollback/--server`, UI SSE, handoff). What it adds over `main`, merged from the `feat/agent-board-local-server-*` branches:
  - `HOST` env: the backend's listen address (default `0.0.0.0`).
  - `ALLOWED_HOSTS` env: answers 421 to any other `Host` header except `/healthz` (DNS-rebinding defence for a no-login loopback board). `apps/backend/src/server.ts`, `config.ts`, `allowed-hosts.integration.test.ts`.
  - PGlite driver: a `pglite://[role@]local/<abs dir>` URL runs the backend on in-process PGlite (`apps/backend/src/db/pglite.ts`, optional dependency `@electric-sql/pglite`, `PGLITE_ASSETS_DIR`, `PGLITE_SHARED_BUFFERS`). Limits documented: one session (requests serialised), role boundary by `set local role` only, Postgres 17 vs the core's 16, one process per data dir.
  - `AGENT_BOARD_CREDENTIALS_COMMAND`: the CLI takes token and data key from an executable (meant for the macOS Keychain) instead of `env` (`apps/cli/src/config/credentials-source.mts`).
  - Feature `version.machine`: the `version` answer names the machine a token belongs to; `board init` takes the machine name from it and `--machine` becomes a check.
  - `board internal shutdown [--grace]`: pauses every running worker, then stops the rest (`apps/cli/src/setup/shutdown.mts`).
  - `board internal units`: prints the worker units as JSON (schema 1) for packagers (`apps/cli/src/setup/worker-units.mts`), one model shared by launchd, systemd and the listener.
  - Worker ends a run cleanly when the machine shuts down; kill-timer and `--kill-whom` fixes; frozen-clock fixes for `TaskBadges`/`TaskCard` tests; cheaper New task tests.
- Docs: `README.md`, all of `docs/` (architecture, cli, development, encryption, first-steps, machine-api, operations, plugins, setup, ui-api, usage, workers).
- Wiki (main clone, git-excluded): `wiki/ab-7fa`, `ab-97f`, `ab-9zr`, `ab-b6j`, `ab-cgi`, `ab-i82`, `ab-nd5`, `ab-xd0`. No `EVALUATION.md` exists in any of them.
- Beads: `bd list --all` has 8 beads; 7 closed, `ab-xd0` in progress. `bd show` read for each.
- Code: `packages/shared/src/{contract,features,sealing}.mts`, `packages/shared/src/ui/*`, `apps/backend/src/{server,machine-api,ui-events,config,index,cleanup}.ts`, `apps/backend/src/trpc/*`, `apps/backend/src/services/**`, `apps/backend/src/db/*`, `apps/frontend/src/**`, `apps/frontend/Caddyfile`, `apps/cli/src/**`, `.github/workflows/*`.

Status vocabulary used in the tables:

- **works**: built, and an automated test covers it (test file named where known).
- **unproven**: built, but no test, or only checked by hand / never in a real browser, real timers, real launchd/systemd or Bun.
- **broken**: a known bug or flake.
- **discussed-not-built**: only in the wiki, beads or docs as deferred, out of scope or follow-up.

Paths: `B/` = `apps/backend/src/`, `FE/` = `apps/frontend/src/`, `CLI/` = `apps/cli/src/`, `SH/` = `packages/shared/src/`.

## 3. Wire contracts today

### Machine API (CLI ↔ server)

- Transport: `POST /api/machine/<command>` JSON `{id?, all?, machine?, author?, run?, body?}` → `{result}` or `{error}`; `POST /api/machine/transcript`; `GET /api/machine/events` (SSE). Auth: bearer `abm_` token, checked before the body.
- Commands (42): `version`, `list-tasks`, `get-task`, `attach-session`, `add-task`, `update-task`, `configure-task`, `edit-prompt`, `claim-task`, `add-note`, `read-notes`, `ask`, `add-pr`, `remove-pr`, `set-pr-states`, `set-pr`, `set-pr-state`, `set-watches`, `ack-watch-stops`, `set-dirs`, `set-catalog`, `set-usage`, `set-feeds`, `ack-feed-requests`, `list-machines`, `get-agents`, `set-agents`, `get-title-rules`, `apply-title-rule`, `heartbeat`, `pause`, `fail`, `stopped`, `run-inbox`, `ack-messages`, `wait`, `wake`, `add-schedule`, `list-schedules`, `update-schedule`, `edit-schedule`, `remove-schedule`. Spec: `docs/machine-api.md`, types in `SH/contract.mts`.
- Every content field is a sealed `abe1.` envelope; the CLI seals with keys derived from the data key and the owner name (`SH/sealing.mts`).

### Browser API (UI ↔ server)

- tRPC 11 over `/trpc` (httpBatchLink, no transformer), cookie session, same origin, no CORS. No subscriptions.
- Procedures: `me`, `revision`, `ui.version`; `auth.{config, logout, oidc.start/finish, saml.start/finish, passkey.loginOptions/login/signupOptions/signup, handoff.start/describe/approve/finish}`; `passkeys.{list, registerOptions, register, rename, remove}`; `keys.{get, setup, replaceSlots}`; `tasks.{list, get, create, fork, answer, dismissQuestion, reply, send, stop, applyPolish, edit, done, rerun, setPriority, configure, setNotBefore, wakeNow, takeBack, removePr, stopWatch, setClosed, move}`; `schedules.{list, setPaused, update, remove}`; `machines.{list, catalogs, advertisedCli, issue, revoke}`; `feeds.{list, request}`; `agents.shared`; `links.{get,set}`; `titleRules.{get,set}`; `transcript.{runs, events, context, output}`; `account.{summary, export, import, delete}`.
- Events: `GET /api/ui/events` SSE (`changed`, no payload, 25 s ping). The bundled app does not use it; it polls every 5 s.
- Other routes: `GET /healthz`, `POST /api/auth/saml/acs`.
- Published surface for other UIs: `docs/ui-api.md`, `SH/ui/procedures.mts` (`UI_PROCEDURES`), `SH/ui/wire.mts`, `SH/ui/version.mts`, shared sealers/openers and `PlainBoard`. `@agent-board/shared` is private and consumed by the desktop client as a git dependency pinned to a fork SHA.

### Version negotiation

| Number                                               | Value     | Where                 | Meaning                                                    |
| ---------------------------------------------------- | --------- | --------------------- | ---------------------------------------------------------- |
| `API_VERSION`                                        | 9         | SH/contract.mts       | break level the server speaks                              |
| `MIN_CLIENT`                                         | 9         | SH/contract.mts       | oldest CLI level the server serves                         |
| `MIN_SERVER`                                         | 9         | SH/contract.mts       | oldest server level the CLI accepts                        |
| `LEGACY_CONTRACT`                                    | 9         | SH/contract.mts       | `contract` reported to CLIs ≤ 0.7.0, which compare exactly |

- Features: `SH/features.mts`. Baseline 5 (`attach-session`, `events`, `note.polish`, `note.suggestion`, `wait`) plus 33 added (`task.model` … `machine.list`; `version.machine` on `local-server-v2` only). UI features: `events`, `handoff`. Client capability: `schedule.after`. Additive changes add a feature name and bump nothing.
- **What the CLI breaks on:** server `api.minClient` above its level (CLI stops itself, listener exits 1, tick tries auto-update); server below `MIN_SERVER` (tick logs `skipped:`); data key id mismatch; a missing feature (that command only is refused); a 422 for a status/enum value it did not declare.
- **What the server breaks on:** nothing by version; it marks a too-old machine `incompatible` and the UI shows a banner. Unknown request keys are 400 (strict parsers).
- **What a UI breaks on:** `x-board-ui-api` below `MIN_UI_CLIENT` → 412 before any read or write. The bundled app sends no header and is never refused. A server without `ui.version` (upstream images) is the "needs a newer version" case for the desktop client.
- Coupling to keep in mind: the bundled frontend and backend ship as one deploy, so web↔server skew is never negotiated; the Caddyfile regex pins the cookie shape.

**Upstream sync**

- The fork's `main` is 40 commits ahead of `upstream/main` and is no longer a fast-forward mirror, contrary to the rule in the `pj-agent-board:domain` skill. Every upstream change from now on is a real merge.
- Collision points on every sync: Drizzle migration numbers (fork migrations 0046 task-icon, 0048 title-rules, 0049 task-labels, 0050–0052 feeds), `ADDED_SERVER_FEATURES`, `UI_PROCEDURES`/`UI_SERVER_FEATURES` (conformance tests fail by design when upstream adds a procedure), the CLI version, the `docs/architecture.md` decisions table.
- Moving the sealers into `SH/ui` was an accepted rebase cost (ab-xd0).
- `RELEASE_REPO` points at `mloureiro/agent-board`, so installed CLIs update from the fork, not upstream.
- `local-server-v2` is 18 commits behind `main`, so the packaged local server pins a core without the migration engine, UI SSE or browser hand-off.
- An accidental upstream PR (codeplant-de/agent-board#176) was opened and closed (wiki/ab-9zr).

**What the fork carries that upstream lacks** (fork PRs #8–#52): question/Other tweaks, last directory, task icon, rename, `attach --desktop`, feeds with plugins and integrations (`mloureiro/agent-board-plugins`, MIT), context usage, title rules and labels, focus fix and session drafts, fork release source, `board uninstall`, pinned task panel, the public UI API (versioning, wire types, shared crypto, PlainBoard, UI SSE), browser sign-in hand-off, `list-machines`, migration engine with `--resume/--rollback/--server`.
