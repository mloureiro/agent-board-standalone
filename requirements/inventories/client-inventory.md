# agent-board-client — inventory for agent-board-standalone

Read-only research in the `agent-board-client` repository at `main` = `de4da5b` (2026-11-24).
Sources: `README.md`, `wiki/agent-board-client-*/` (REQUIREMENTS, ARCHITECTURE, RESEARCH,
ITERATION_*, QA_REPORT, E2E_REPORT, ACCEPTANCE, HANDOFF), every bead (`bd list --all`,
`bd show`), PRs #1–#34 and their bodies, `git log`, `src-tauri/`, `src/`, `fixtures/`.
Paths are relative to the repository unless absolute. Bead ids drop the `agent-board-client-`
prefix (e.g. `e81` = `agent-board-client-e81`).

A claim marked `[unverified]` was not read from a file: it comes from an inference or a check
outside the client repository.

Status vocabulary in section 1:

- **works**: merged on `main`, covered by unit tests, and checked in the running app at least once
  (owner or QA run recorded in the wiki or a PR).
- **unproven**: merged, but only unit-tested or not exercised in the running app or against a real
  board. Most manual checklists are deferred to an end-of-roadmap pass and are unrun.
- **broken**: a recorded defect or an open bug bead.
- **discussed-not-built**: an open bead, a deferred item, or an out-of-scope note.

There is **no end-to-end suite of any kind** in this repository (see section 4). Every "works"
below rests on unit tests plus a hand run.

## 3. What the shell does to a loaded page, and what it must never do

### Does today (`main`)

- **Hosting.** One window `server-<uuid>` per server, not closable (`board_window.rs:383-388`). Inside: a tab-bar child webview `tabbar-<uuid>` (`tabbar.html`) and one content child webview per tab (`board-<uuid>-home|N`, or `native-<uuid>-…` for native pages). No iframe anywhere.
- **Data store.** Every content webview of a server uses that server's persistent store (`data_store_identifier(uuid)` on macOS; `app_data_dir/webviews/<uuid>` elsewhere) (`webview_store.rs`, `board_window.rs:58-74`).
- **Injected scripts** (main frame):
  - `src-tauri/scripts/external-links.js`: turns a plain left-click on a cross-origin `a[href]` into `window.open(…, '_blank', 'noopener')`.
  - `src-tauri/scripts/tab-routing.js` (role `home` or `tab`): wraps `history.pushState/replaceState` and `popstate` to open or report routes; captures Ctrl-Tab and Cmd/Ctrl-`+`; replaces `window.Notification` and `ServiceWorkerRegistration.prototype.showNotification` with stand-ins (forwarding from 🏠 only); wraps `window.fetch` to watch `/trpc*` responses and probe `/trpc/me` for health.
  - All signals leave the page as navigations to `agent-board-client:<verb>?…`, which `on_navigation` intercepts and always cancels (`sentinel.rs`). Notify and health are accepted only when the sender's current URL is on the server's origin.
- **Navigation.** `on_navigation` allows every non-sentinel URL in place; `on_new_window` always denies and routes: same-origin → new tab, same-origin `/handoff/` → default browser, other http(s) → default browser, other schemes → dropped (`link_route.rs`).
- **WebKit tweaks.** Disables Backspace back-navigation via the private `_setBackspaceKeyNavigationEnabled:` (guarded by `respondsToSelector`) (`webkit_prefs.rs`); zoom per server (`zoom.rs`); 🏠 runs with background throttling disabled.
- **Reads from the page.** Document title (tab label) and page-load URL (route) when on the server origin.
- **Native requests outside the page.** A pre-open GET of the server URL (`connection.rs`); for native pages, Rust-side tRPC calls with the keychain cookie, a handshake, and an SSE relay (`board_api.rs`, `handshake.rs`, `board_events.rs`).

### Must never do (constraints in the skill and the code)

- **Never frame a board.** The server sends `frame-ancestors 'none'`; each server is a top-level navigation (skill; d0e AC6).
- **Never expose native commands to a board page.** `capabilities/main.json` (window `main` only), `tabbar.json` (webviews `tabbar-*`), `native.json` (webviews `native-*`, label-matched only, "a window match would hand these permissions to the board pages"). No capability lists a remote URL. An explicit AppManifest in `build.rs` and the exact pin `tauri = "=2.12.6"` guard against the pre-2.11.1 hole where "a remote page could invoke every app command" (`Cargo.toml:19-21`). Commands re-check the caller's webview label (`commands.rs:147-186`).
- **Never handle credentials for a board page.** No passphrase, data key or plaintext in the shell (d0e AC10). Native pages: the session token lives in the keychain and is sent only from Rust, never to JS; `auth.*` procedures are refused from `board_call`; probes carry no session.
- **Never open the identity provider in another window during a redirect sign-in.** OIDC/SAML verifiers live in the tab (skill; c4n D23).
- **Never share storage between servers**, even two entries for the same address (d0e AC7).
- **Never trust page signals.** Origin check, length caps, plain-path check, 10 notifications per server per minute.
- **Never log URLs, paths, labels or titles** (d0e X3).
- **App CSP** (own pages only: list, tab bar, `board.html`): `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src ipc: http://ipc.localhost; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` (`src-tauri/tauri.conf.json`). Board pages keep their server's CSP. Native pages may navigate only to the app's own `board.html` (`native_page.rs:16-22`).

## 5. If the client wrapped a browser client built in the same repository

Today the shell loads each remote server's own page and patches it from outside. The proposal:
the client app bundles the browser client (part 4) and that client talks to one or more APIs
(part 1) through a versioned contract.

### Simpler

- **No page patching.** `tab-routing.js`, `external-links.js`, the sentinel scheme, the `Notification` / `fetch` / `history` wrappers and title scraping go away: the browser client raises notifications, reports routes, health and titles through a defined bridge or its own code (removes P-07, P-14, P-15, P-16, P-17).
- **One build, one version.** UI and client ship together, so "board UI vs shell" skew disappears; the only skew left is client ↔ API, behind one version handshake (P-01, P-06 become a single contract test).
- **Testable in a browser.** The browser client can run under Playwright against a real API; the native wrapper's own surface shrinks to windows, keychain, notifications, links, updates.
- **Sign-in.** One sign-in path implemented once (the hand-off already built for native pages, APP-073), not per server-page variant; passkeys can go through the default browser by design.
- **Projects / several servers in one window.** Without the `frame-ancestors 'none'` constraint on remote pages, one UI can show several servers and projects side by side (APP-100, APP-059).

### Harder

- **Origins and stored keys.** All servers' data now share the app's single origin. Per-server keys (today isolated by one WebKit data store per server) need explicit per-server namespacing in IndexedDB/keychain, and a compromised or hostile server's data must never reach another server's state. Removing a server must delete exactly its slice. Existing users' keys in today's per-server stores do not migrate: one unlock per server again.
- **Cross-origin API access.** The page can no longer call the server same-origin: either CORS + cookies on every server (and `SameSite` / `__Host-` rules on a `tauri://` origin), or every request goes through Rust as fw3/s9g already do (larger native surface, streaming through IPC).
- **Hostile server content.** Server data rendered in a page that holds native commands: the threat model moves from "page gets nothing" to "server data must never reach command-capable code unescaped".
- **Compatibility with many server versions at once.** One bundled UI must speak to several API versions (hosted upstream, fork, local) simultaneously; the server can no longer ship a UI fix to its users, so every UI change needs a client release.
- **Updates.** Becomes mandatory: no auto-updater exists today and builds are ad-hoc signed and not notarized. Signing also governs keychain access across builds and passkey entitlements.
- **Offline.** The UI loads offline (good), but each server's state must render a clear offline / signed-out / too-old state per server, instead of the server's own error page.
- **Plain browsers lose nothing only if** the browser client also runs standalone (served by the API or static): the hand-off, cookie and CORS choices must work in both.
